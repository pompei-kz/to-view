# Правила to-view

- Исполняемый файл to-view должен работать без установленных внешних библиотек времени выполнения. Связывай Rust, FFmpeg, SDL2, системную C-библиотеку и остальные нативные зависимости статически. Не загружай разделяемые библиотеки во время работы и не запускай внешние программы для воспроизведения.
- Держи логику воспроизведения, перемотки и интерфейса в Rust. Используй FFmpeg и SDL2 через библиотечные API.
- Собирай приложение через Cargo. Нативные исходники и сборочные артефакты держи в каталоге сборки. Фиксируй версии и контрольные суммы загружаемых исходников.
- Сохраняй запуск `to-view /path/to/video.mp4` с немедленным воспроизведением. Разбирай новые опции в Rust и передавай настройки плееру через `player::Options`.
- После изменений сборки проверь релизный ELF через `readelf -l -d target/release/to-view`. В нём не должно быть интерпретатора `INTERP` и записей `NEEDED`.

## Сообщения коммитов

Пиши заголовок и подробное описание каждого коммита на английском языке.

Первая строка имеет формат:

```text
TYPE(very-short-first-comment): short description of the first topic + short description of the second topic
```

В скобках указывай очень короткое обозначение первой темы. После двоеточия кратко перечисляй темы коммита через ` + `. Если тема одна, укажи только её. После пустой строки добавь более подробное описание каждой темы.

Допустимые типы:

- `feat` — добавление новой функции.
- `fix` — исправление ошибки.
- `plan` — составление или корректировка плана, добавление промпта пользователя.
- `devops` — инфраструктурные задачи, включая пайплайны и настройку рабочих процессов.
- `doc` — изменения документации, включая переводы.

Если для какой-либо темы нужен тип вне этого списка, остановись до создания коммита. Опиши тему пользователю и предложи варианты обозначения типа. Дождись, пока пользователь выберет вариант или предложит свой.

## Работа с планами

- Храни план и промпты в каталоге задания. Имя плана — `NN-PLAN-<task>.md`, где `<task>` берётся из имени исходного файла `NN-prompt-<task>.txt`. Используй короткое описание задачи с дефисами вместо пробелов.
- Каждое уточнение к заданию копируй в отдельный файл `NN-prompt-<short-comment-of-addition>.txt` дословно, сохраняя формулировки и переносы строк. Используй короткое описание уточнения с дефисами вместо пробелов. Учитывай уточнение при обновлении плана.
- Нумеруй промпты в порядке поступления внутри каталога задания, начиная с `01`. Номер плана всегда должен быть больше номеров всех промптов. После добавления уточнения при необходимости переименуй файл плана, присвоив ему номер на единицу больше максимального номера промпта. При сортировке по имени план должен идти последним.
