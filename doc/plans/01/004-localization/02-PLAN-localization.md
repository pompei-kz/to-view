# Многоязычность toview

Исходный запрос — [01-prompt-localization.txt](01-prompt-localization.txt).

## Результат

При старте плеер выбирает язык по заданному порядку переменных окружения. Русский, английский и казахский переводы включены в исполняемый файл. Переводы других языков читаются из установленных файлов GNU gettext `.mo`. Если все кандидаты не подошли, используется встроенный русский. Выбранный язык применяется к меню, справке и собственным сообщениям об ошибках.

## Структуры и ресурсы

1. Ввести модуль `i18n`. Неизменяемая структура `Translations` содержит выбранный идентификатор локали, источник `Builtin` или `Mo` и таблицу переводов. Создать её в начале `main` до разбора аргументов. Передавать ссылки в UI и `Arc<Translations>` в рабочий поток. Не изменять глобальную локаль процесса и не читать окружение при каждом выводе.
2. Использовать стабильные английские `msgid` в качестве ключей gettext. Предусмотреть контекст `msgctxt` и формы множественного числа. При отсутствии или пустом переводе использовать встроенный русский перевод соответствующего ключа. Для динамических строк применять именованные заполнители, например `{key}` и `{frame}`. Подставлять значения после перевода, проверять совпадение заполнителей и при ошибке использовать русский шаблон.
3. Хранить исходные `.po` для `ru`, `en`, `kk` в проекте. При сборке преобразовывать их в `.mo` и включать в бинарник. Все три каталога должны содержать полный одинаковый набор ключей и корректные `Plural-Forms`. Встроенный и внешний `.mo` обрабатывать одним загрузчиком. Использовать уже готовую Rust-библиотеку gettext, если она поддерживает формат, множественные числа, статическую сборку и требования ниже.
4. Внешний каталог искать по домену `toview` в `/usr/local/share/locale/<locale>/LC_MESSAGES/toview.mo`, затем в `/usr/share/locale/<locale>/LC_MESSAGES/toview.mo`. Для каждой локали перебирать варианты от наиболее конкретного к языку, сохраняя значимый модификатор. Например, для `sr_RS.UTF-8@latin` проверить `sr_RS@latin`, `sr@latin`, `sr_RS`, `sr`; для `de_DE.UTF-8` — `de_DE`, `de`. Сначала для конкретного варианта проверить оба корня, затем перейти к следующему варианту. Выбирать первый успешно загруженный каталог целиком.
5. Проверять сигнатуру, порядок байтов, версию, диапазоны таблиц, строки и заголовок каталога `.mo`. Декодировать строки из кодировки `Content-Type` в UTF-8 с помощью встроенного в бинарник Rust-кода. Повреждённый каталог или неподдерживаемая кодировка означает неудачу текущего файла и продолжение поиска. Правило `Plural-Forms` вычислять проверенной библиотекой либо ограниченным интерпретатором GNU gettext без выполнения произвольного кода. При некорректном правиле для соответствующего сообщения применять русский fallback.
6. Для `ru`, `en` и `kk` всегда использовать встроенные каталоги, включая региональные варианты, без зависимости от наличия `.mo` на диске. Технические значения, имена файлов, номера и клавиши передавать в перевод как параметры.

## Локаль и признак успеха

- Принимать имена вида `language`, `language_REGION`, `language_REGION.encoding`, `language_REGION@modifier` и их сочетания. Нормализовать регистр языка и региона. Отклонять пустые и некорректные значения, разделители пути и управляющие символы. `C`, `POSIX` и `C.UTF-8` считать неудачей, поскольку они не задают язык приложения.
- Для `LC_ALL`, `LC_MESSAGES` и `LANG` проверять установленность точной системной локали через `newlocale(LC_MESSAGES_MASK, имя, NULL)`. Освобождать объект через `freelocale`. При ошибке пробовать следующую переменную. Этот вызов не меняет глобальную локаль. После проверки нужен встроенный язык или корректный внешний `.mo`.
- `LANGUAGES` трактовать как список через двоеточие. Обрезать пробелы вокруг элементов и пропускать пустые элементы. Для коротких имён языка `ru`, `en`, `kk` считать встроенный перевод достаточным признаком установленности; для остальных коротких имён таким признаком является корректный `.mo`. Элементы с регионом, кодировкой или модификатором дополнительно проверять через `newlocale`. Использовать именно имя `LANGUAGES`, указанное в задании.

## Псевдокод выбора

```text
функция попробовать(значение, источник):
    если значение отсутствует или пусто:
        вернуть НЕУДАЧА
    локаль = разобрать_и_проверить_имя(значение)
    если локаль некорректна или это C / POSIX / C.UTF-8:
        вернуть НЕУДАЧА

    если источник = LANGUAGES и локаль содержит только язык:
        установлен = true
    иначе:
        установлен = проверить_через_newlocale(исходное_имя)
    если не установлен:
        вернуть НЕУДАЧА

    если локаль.язык = ru: вернуть встроенный_MO_RU
    если локаль.язык = en: вернуть встроенный_MO_EN
    если локаль.язык = kk: вернуть встроенный_MO_KK

    для имени в варианты_каталога(локаль):
        для корня в [/usr/local/share/locale, /usr/share/locale]:
            путь = корень / имя / LC_MESSAGES / toview.mo
            если файл читается и содержит корректный MO:
                вернуть загруженный_каталог(путь)
    вернуть НЕУДАЧА

для имени в [LC_ALL, LC_MESSAGES, LANG]:
    результат = попробовать(окружение[имя], имя)
    если результат успешен: использовать его и завершить выбор

для элемента окружение[LANGUAGES], разделённого двоеточием:
    результат = попробовать(элемент, LANGUAGES)
    если результат успешен: использовать его и завершить выбор

использовать встроенный_MO_RU
```

## Интеграция

1. Инвентаризировать пользовательские строки CLI, меню, аудио, ошибок воспроизведения и сохранения окна. Вынести собственные сообщения в каталог. Ошибки FFmpeg и ОС передавать параметрами, сохраняя исходные технические детали. Локализовать справку и ошибки разбора аргументов до запуска SDL.
2. Заменить строку меню переводимыми шаблонами с обозначениями клавиш и номером кадра. Учитывать длину перевода, узкое окно и смену раскладки. Встроить шрифтовые ресурсы с покрытием символов всех поддерживаемых встроенных языков и предусмотреть выбор встроенного резервного шрифта для внешнего перевода, чтобы буквы не превращались в пустые квадраты.
3. Документировать формат и размещение каталогов, порядок переменных, установку языка и создание нового `.po`/`.mo` в README. Обновить сборку и lock-файл. После фактического завершения реализации и проверок изменить статус этого плана.

## Проверка

- Проверить порядок `LC_ALL → LC_MESSAGES → LANG → LANGUAGES → ru`, неустановленные и некорректные локали, пустые значения, `C`, несколько элементов списка и приоритет встроенных переводов. Использовать изолированное окружение и подменяемую проверку установленности; отдельно проверить реальный `newlocale`.
- Проверить три встроенных языка без внешних `.mo`, перевод дополнительного языка через временный `.mo`, региональный поиск, неполный перевод, некорректный каталог, кодировки, контексты, множественные числа и заполнители. Сверить правильность заголовков и полноту встроенных каталогов.
- Проверить меню, смену раскладки, номер кадра, узкое окно, CLI-справку и ошибки на выбранном языке. Включить пример внешнего языка с отличным набором символов.
- Выполнить `make`, проверить отсутствие `INTERP` и `NEEDED` через `readelf -l -d target/release/toview`, запуск с пустым `PATH` и использование встроенных переводов без внешних файлов или разделяемых библиотек.
